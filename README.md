# FlyEcho

**Drosophila-connectome-inspired active sensing for obstacle detection.**

FlyEcho is a research/education repository that uses a small spiking neural network inspired by known *Drosophila* looming/escape circuitry to control an **ultrasonic emitter**, process echoes, and detect approaching objects.

> **Biological honesty:** a fruit-fly brain is not an ultrasonic radar and does not itself emit useful ranging waves. In FlyEcho, the "brain" is a computational model. A physical transducer emits the pulse; the neural model decides *when to ping* and interprets returned echoes.

## Why this is interesting

The system closes a real active-sensing loop:

```text
           echo-derived features
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
   LC4-like              LPLC2-like
        └──────────┬──────────┘
                   ▼
                GF-like
              ┌────┴────┐
              ▼         ▼
          TTMn-like   PSI-like
           jump          │
                         ▼
                     DLMn-like
                       flight
                   │
         adaptive ping command
                   ▼
            ultrasonic sensor
                   │
                 object
                   │ echo
                   └──────────────► range tracker ──► brain
```

As an object approaches, the controller raises the ping rate. A GF-like output neuron produces a discrete `THREAT` event when the estimated time-to-collision becomes small enough, while the model also propagates the event into simplified jump and flight motor branches.

## What it detects

The current demo detects:

- object presence
- distance
- whether the object is approaching or receding
- closing speed
- approximate time-to-collision
- a threat event generated by a spiking escape pathway
- simplified downstream jump/flight pathway activity

The default simulation is deterministic enough to test but contains configurable measurement noise.

## Quick start

Requires Python 3.10+.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows
# .venv\Scripts\activate

pip install -e .
flyecho demo
```

Try a faster approaching object:

```bash
flyecho demo --distance 2.5 --velocity -0.65 --seconds 6
```

Example output:

```text
t= 2.27s  d=1.03m  v=-0.65m/s  TTC=1.58s  ping=22.5Hz  danger=0.70  threat=no
t= 2.69s  d=0.76m  v=-0.68m/s  TTC=1.12s  ping=30.0Hz  danger=0.85  threat=YES
```

## Architecture

### 1. Echo front-end

`EchoSimulator` models a round-trip ultrasonic measurement:

\[
t_\mathrm{echo} = \frac{2d}{c}
\]

where `d` is target distance and `c` is the speed of sound.

### 2. Sensor encoding

Successive range measurements are converted into proximity drive, closing-speed drive, and time-to-collision drive. These values are turned into synaptic current.

### 3. Fly-inspired spiking circuit

The compact network deliberately resembles the *logic* of a Drosophila looming/escape pathway rather than claiming to be a faithful fly-brain simulation:

```text
closing / urgency ─► LC4-like ───┐
                                  ├─► GF-like ─► TTMn-like
proximity / urgency ─► LPLC2-like┘       │
                                         └─► PSI-like ─► DLMn-like
```

Every node is currently a leaky-integrate-and-fire neuron. The downstream TTMn/PSI/DLMn branch is included to make the escape pathway less artificially truncated, but the normalized time constants, thresholds and synaptic currents are engineering parameters rather than fitted biological values.

### 4. Active ping controller

The network output controls sensing density: safe scenes use a lower ping rate, approaching obstacles raise it, and a GF-like spike temporarily drives maximum sampling. This makes the system **active**, not just a passive classifier.

## Biological grounding

The sensory part of the circuit motif is based on established Drosophila looming-escape results: LC4 and LPLC2 provide complementary looming information and both synapse directly onto the Giant Fiber. The downstream extension follows the established giant-fiber escape pathway: GF drives the tergotrochanteral motor neuron (TTMn) and the peripherally synapsing interneuron (PSI), while PSI relays activity to dorsal longitudinal muscle motor neurons (DLMn).

FlyEcho does **not** claim that these neurons natively process ultrasound; echo features are deliberately mapped into analogous computational channels. It also does not claim that the simple LIF parameters reproduce measured Drosophila membrane dynamics.

Useful background:

- Ache et al. (2019), *Neural Basis for Looming Size and Velocity Encoding in the Drosophila Giant Fiber Escape Pathway*, Current Biology. DOI: `10.1016/j.cub.2019.01.079`.
- Klapoetke et al. (2017), *Ultra-selective looming detection from radial motion opponency*, Nature. DOI: `10.1038/nature24626`.
- Bates et al. (2023), *retro-Tango enables versatile retrograde circuit tracing in Drosophila*, eLife, for the GF → TTMn/PSI escape pathway description.

### Simulator scope

The built-in LIF implementation is intentionally tiny and dependency-free so the default demo remains easy to install and inspect. For substantially larger neuron populations or biophysically richer experiments, a mature simulator such as **Brian2** is a better direction than extending the custom integrator indefinitely. GeNN becomes more attractive mainly when simulations are large enough to justify GPU-oriented code generation.

## Hardware mode

`firmware/esp32_ultrasonic/esp32_ultrasonic.ino` is a minimal ESP32 + HC-SR04 bridge. The firmware emits `RANGE,<metres>` and accepts `PING_HZ,<frequency>` commands, so the host model can control the physical sensor's sampling rate.

```bash
pip install -e ".[hardware]"
flyecho hardware --port COM3
# Linux example: flyecho hardware --port /dev/ttyUSB0
```

### Wiring

| HC-SR04 | ESP32 |
|---|---|
| VCC | 5V |
| GND | GND |
| TRIG | GPIO 5 |
| ECHO | GPIO 18 through a safe level divider |

Do **not** feed a 5 V HC-SR04 ECHO signal directly into a 3.3 V ESP32 input.

## Optional FlyWire data adapter

The full adult-fly connectome contains roughly 140k neurons and tens of millions of synapses. FlyEcho does **not** pretend that loading the connectome magically creates sonar.

The generic edge-list loader in `flyecho.connectome` lets you download a public FlyWire connectivity table, select a biologically interesting subgraph, inspect weighted connectivity, and later replace the compact hand-built circuit with a data-driven circuit. See `data/README.md`.

## Design principles

1. **No fake biology.** The README states exactly which parts are biological inspiration and which are engineering.
2. **Closed-loop sensing.** Neural state changes the sensor's future sampling.
3. **Reproducible tests.** The threat detector and downstream escape propagation are covered by unit tests.
4. **Hardware optional.** Everything runs in simulation first.
5. **Connectome-ready.** Public FlyWire data can be introduced later without rewriting the whole project.
6. **Use mature simulators when scale justifies it.** The local LIF model is for the compact demo, not a replacement for Brian2 or GeNN.

## Safety and scope

FlyEcho is for benign sensing, robotics, education and neuroscience-inspired computing. It does not contain covert surveillance functionality or any mechanism for identifying people.

## Validation

Before release, the repository is checked with unit tests covering the LIF neuron, range tracking, threat circuit, downstream TTMn/PSI/DLMn propagation, connectome CSV parsing, and hardware protocol helpers. GitHub Actions repeats the test suite on every push and pull request.
